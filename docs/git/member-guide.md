# Git の使い方(メンバー向け)

VS Code のメニュー「ターミナル」→「タスクの実行」から **作業開始・ブランチ切り替え・提出** を選ぶだけで、Git の操作はすべて自動で行われます。Git の仕組みを知らなくて大丈夫です。費用は 0 円です。

前提: GitHub のアカウントを持っていて、VS Code を普段から使っていること。

## 1. 初回の準備(約 10 分)

1. **招待を承諾してから、クローンする。** チームのリーダーからの招待メールの **Accept invitation** を押す。次に VS Code で Ctrl + Shift + P →「Git: Clone」(リポジトリの複製)を選び、チームのリーダーから伝えられた URL を貼る。保存先は「ドキュメント」などでよい。途中でブラウザに GitHub のログイン画面が出たら、自分のアカウントでログインする(初回だけ)。二段階認証(2FA)の設定を求められたら、**SMS** か **パスキー**(スマホの指紋・顔認証)で設定する
2. **開いて、信頼する。** 「複製したリポジトリを開きますか?」で **開く**。「作成者を信頼しますか?」には **はい、作成者を信頼します**。これで準備完了

うまくいかないとき:
- VS Code が「Git が見つかりません」と言う: https://git-scm.com/download/win からインストールして(「次へ」で進めてよい)、VS Code を開き直す
- 「リポジトリが見つかりません」と出る: 招待を承諾していないか、別のアカウントでログインしている。チームのリーダーに GitHub のユーザー名を伝える
- 最初のタスク実行時に「名前とメールの設定が必要です」と出る: 画面に表示された 2 行をターミナルにそのまま打って、もう一度実行する。メールは GitHub の Settings → Emails にある `数字+ユーザー名@users.noreply.github.com` を使う

## 2. 毎日の使い方

メニュー「ターミナル」→「タスクの実行」を開き、4 つから選びます。画面下に結果が出ます。

| 選ぶもの | いつ | 聞かれること | 裏で起きること |
|---|---|---|---|
| **作業開始** | チケット(Issue)に取りかかるとき。朝いちばんや、main の最新を取り込みたいときにも | Issue の番号。短い英語の名前は省略可 | 最新の状態を取ってきて、あなた専用の作業場所を用意する。前に同じ番号で始めていれば、そこに戻って main の変更を取り込む |
| **ブランチ切り替え** | 他の人の作業を見るとき | 一覧から番号 | その人の作業場所に切り替える。見終わったら「作業開始」で自分の番号を入れれば戻れる |
| **提出** | チケットの作業が一通りできたとき | なし(先に PR.md を書く) | 作業を GitHub に送り、提出ページをブラウザで開く |
| **やり直し(main に戻る)** | 「切り替えられませんでした」などで先に進めないとき | 実行してよいかの確認(y で実行) | 記録していない変更を `local/backup/日時_ブランチ名/` に控えてから元に戻し、main の最新に戻る。控えのフォルダが開く。GitHub には何も送らない |

### 提出のしかた

1. リポジトリ直下の **PR.md** を開き、「やったこと」「レビューで見てほしいポイント」を書き、「提出前のチェック」を確かめて [x] を付ける(「気になっていること」はあれば)
2. 「提出」を実行する
3. ブラウザに提出ページが開く。内容を確認して **Create pull request** を押す
4. チームの誰か(またはチームのリーダー)に「レビューお願いします」と声をかける

直しを頼まれたら、同じ作業場所で直して、もう一度「提出」を実行します(PR.md は書かなくてよい)。自動で反映されます。

### 気をつけること

- 「作業開始」と「ブランチ切り替え」は、その時点の作業をすべて GitHub に送ってから動きます。別の作業場所に移っても、前の作業は消えません
- 作業場所をまたいで内容を持っていきたいときは、メモ帳などに写してから移動してください
- 他の人の作業場所では、動かして確認するだけにして、ファイルは編集しないでください
- 「チームのリーダーに相談してください」と表示されたら、画面の文章をそのまま伝えてください。画面に出た **ログファイル**(`local/logs/...` で始まる場所)も見せてください

## 3. 困ったとき

| 症状 | 対処 |
|---|---|
| 「タスクの実行」に 4 つが出ない | フォルダを開き直す(ファイル → フォルダーを開く → クローンしたフォルダ)。それでも出なければチームのリーダーへ |
| 実行してもすぐ閉じる、何も起きない | Git が入っていないか、入れた場所が違います。チームのリーダーへ |
| GitHub のログイン画面が出た | 自分のアカウントでログインする。初回と、長く使わなかったときに出ます |
| 「名前とメールの設定が必要です」 | 表示された 2 行をターミナルに打ってから、もう一度実行する(1 の「うまくいかないとき」) |
| 「数字で入力してください」 | Issue の番号(チケットの # の後ろの数字)を入れる |
| 「PR.md に説明を書いてから」 | PR.md を書いてから、もう一度「提出」 |
| 「main からは提出できません」 | 「作業開始」を先に実行する |
| 「切り替えられませんでした」「やり直し(main に戻る)を実行してください」 | 「やり直し(main に戻る)」を実行する。変更は `local/backup/` の控えに残るので、「作業開始」で自分のブランチに戻ってから必要な内容を写す。控えは不要になったら消してよい |
| 「衝突しました」「チームのリーダーに相談してください」 | 画面の文章と、画面に出たログファイル(`local/logs/...`)をそのままチームのリーダーに伝える。自分で直そうとしない |

チームのリーダーに相談するときは、画面に出たログファイル(`local/logs/...`)も見せてください。ログには、何が起きたかの記録が入っています。ログは自分のパソコンの中にだけ残り、GitHub には送られません。

## 4. 守ること

- パスワードや個人情報をファイルに書いて置かない(`.env` という名前のファイルは送られない設定になっていますが、それ以外のファイルに書けば送られます)
- `.vscode`、`scripts`、`tests`、`docs/git`、`PR.md` の雛形の部分は編集しない。変えたいことはチームのリーダーに相談
- 分からないときは、そのまま進めずチームのリーダーに聞く
